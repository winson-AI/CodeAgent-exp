# 适配器生成器指南

本指南说明如何将一个 Compose 组件库转换为 `react-to-compose-ui` 适配器包。

## 目标

生成一个可复用的知识包，帮助 `react-to-compose-ui` 将经过校验的 React 语义映射到某一个特定的 Compose 库，且无需改动主翻译工作流。

## 需确定的配置项

在编写文件前，先锁定以下配置：

- 适配器编号（adapter id）
- 展示名称（display name）
- 库包前缀（library package prefixes）
- 用于判定当前库是否可用的外壳标识（shell signals）
- 需要设置一级别名的语义项
- 需要显式降级为原生 Compose 的区域

## 文件存放位置

将草稿包生成至当前工作目录，示例：

`./compose-adapter-<adapterId>/`

生成过程中不要直接写入固定的运行时技能目录。

取而代之需准备：

- 可直接拷贝使用的适配器包目录
- 用于后续手动录入到 `skills/react-to-compose-ui/adapters/registry.json` 的注册表配置片段

## 文件用途说明

### `manifest.json`

用于存放稳定的库标识与选择提示：

- `id` 编号
- `displayName` 展示名称
- `framework` 框架类型
- `selectionHints` 选择提示
- 可选元数据：`packagePrefixes` 包前缀、`fallback` 降级配置、`notes` 备注说明

### `aliases.json`

将界面语义映射到对应库的组件。

优质别名特征：
- 匹配置信度高
- 可在多页面中复用
- 减少检索冗余干扰

劣质别名特征：
- 完整复刻所有组件目录
- 记录样式细节而非语义定义
- 用低匹配度强行覆盖不支持的业务区域

### `component_knowledge.json`

作为核心知识库，以组件名作为键值存储。

每个组件可按需包含以下任意内容：
- 功能描述
- 接口定义
- 属性配置
- 事件回调
- 简短示例代码

无需强制所有组件使用统一层级结构。

### `component_knowledge.jsonl`

可选文件。仅用于存放复杂示例，避免主 JSON 文件过于臃肿。

### `prompt.md`

保持内容简洁，用于说明：
- 优先使用当前库的场景
- 需要降级适配的场景
- 导入与主题约束规则
- 防重复编写规范
- 图标与资源使用注意事项

请勿在此文件粘贴大段代码示例。

## 推荐生成流程

1. 查阅官方文档与示例代码
2. 筛选翻译页面中高频出现的 5-20 个核心组件
3. 仅为关键语义配置别名
4. 精简编写组件知识库内容
5. 仅在必要时补充 JSONL 示例
6. 使用 `--adapter-dir` 参数运行校验器
7. 在适配器包旁准备注册表配置片段
8. 根据校验结果与实际翻译反馈，针对性完善适配器包

## DUX 参考范例

可参考 `skills/react-to-compose-ui/adapters/dux/` 作为基准示例，参考维度包括：
- 注册表条目格式
- 清单文件结构
- 提示文档篇幅
- 别名划分粒度
- 组件知识库详细程度
